# Review artifact — M5 routing (2026-11-16)

Source: review sub-agent `ses_e1c4c60f3ffeYqDu6532httRvL`, deep review of the
uncommitted M5 work on top of `b1e58f0`. Verdict: **needs changes** — 6 major,
6 minor, 5 nits. Verified sound: scoring determinism (SQL-ordered candidates,
total-order comparator, no NaN on degenerate pools), grants/budgets cannot be

## Major (resolutions recorded as D24-D27)

- **M1.** Breaker counts client-fault failures: `record_breaker_failure` is
  unconditional on failure class (`chat.rs:1703-1707, 1895-1906, 2001-2002`);
  an upstream 400 (`invalid_request`) trips the breaker — one bad client
  integration excludes a healthy offering for everyone. Fix: skip breaker
  recording for `invalid_request`/`internal` (a `counts_toward_breaker` flag on
  `FailureClass`).
- **M2.** Breaker explanation says `trips()` (times opened) is "consecutive
  failures" (`chat.rs:1177-1182`) — the honesty surface prints wrong numbers.
  Fix: expose `consecutive()` or reword; the test never checked the number.
- **M3.** Presets don't match their contract: penalties apply under every
  preset (`routing.rs:494-499`), so `cheapest` can pick a pricier offering.
  **Resolution: D24** — single-component presets are pure orders, no
  penalties.
- **M4.** Quality scale is mixed: overrides accept any finite number while
  benchmarks are Elo-scale; a `0.99` override silently ranks last after
  min-max. **Resolution: D25** — one scale, validated overrides.
- **M5.** Reliability is blind to failover-recovered failures (one
  `usage_events` row per request — the rescued attempt leaves no sample) and
  counts credential-side 402/429 against the offering.
  **Resolution: D26** — per-attempt samples; quota classes belong to the
  credential.
- **M6.** No warm-up or sample-count weighting (D5 promised one): 1 sample
  fully defines speed/reliability; min-max amplifies tiny spreads.
  **Resolution: D27** — shrink toward 0.5 by `n/(n+10)`, trusted at 10+.

## Minor

- **m1.** `TelemetryStore::warm` never called in production (`main.rs:124`);
  `telemetry_snapshots` is write-only despite the docs. Wire it or drop the
  claim.
- **m2.** `breaker::is_recovering` is dead code with a promise in its doc.
- **m3.** Half-open is not "one probe" (`breaker.rs:14-16` vs `is_open`):
  N concurrent requests pass and the first success closes.
- **m4.** `combo:` shadows real model ids (`require_name` permits `:`) and
  combos are undiscoverable (`list_v1_models` omits them).
- **m5.** `explain_outcome` can say "no candidate was attempted" after
  attempts were made (`chat.rs:603-605`).
- **m6.** `GATEWAY_BREAKER_THRESHOLD` silently truncates (`as u32`).

## Nits

`Score.total` escapes [0,1] (penalties; `member_weight > 1`) with no caveat in
`decision_json`; penalties not scaled by `member_weight`; benchmark tie-break
prefers category `code` over `text` (undocumented); `rr_cursor` advances even
for budget-refused requests; the spec lacked the 401-in-combo deviation and
said "pool median" where the code imputes a flat 0.5.

## Test gaps each finding maps to

No test that a 400 trips the breaker (M1); the breaker-explanation test never
checks the number (M2); the `cheapest` fixture cannot expose the penalty flip
(M3); no mixed-scale quality test (M4); no failover-attribution test (M5); no
minimum-sample test (M6); nothing verifies `warm()` wiring (m1). Suggested
strengthening: an invariant property over randomized pools (components in
[0,1], no NaN, output is a permutation of the eligible input).
