## Major findings

1. **Audit pagination drops entries on timestamp ties** — `routes/audit.rs:104-116`.
   Query orders by `occurred_at DESC, id DESC` but the cursor filter is
   `occurred_at < ?`. A page boundary inside a group of rows sharing one
   millisecond excludes the remaining same-timestamp rows forever. Verified
   against SQLite: 3 rows, same timestamp, `limit=2` → page 2 empty, 1 row
   lost. Fix: composite cursor `(occurred_at, id)` with
   `occurred_at < ?1 OR (occurred_at = ?1 AND id < ?2)`.
2. **`before` cursor mis-normalized for non-UTC offsets** — `routes/audit.rs:82-86`.
   `DateTime::parse_from_rfc3339` returns `FixedOffset`; formatting renders
   wall-clock with a hardcoded `Z`. `before=2026-01-01T12:00:00+02:00` becomes
   `12:00Z` instead of `10:00Z`. Fix: `.to_utc()` before formatting.
3. **The pagination test masks finding 1** — `routes/audit.rs:127-136, 164-227`.
   `spread_timestamps` removes the tie condition the bug needs. Fix: tests with
   deliberately tied `occurred_at` and with a `+HH:MM` cursor.
4. **Client-IP resolution breaks rate limiting and audit IPs behind a proxy** —
   `auth.rs:405-444, 496-505`. `ConnectInfo` is preferred unconditionally:
   behind a reverse proxy every client shares the proxy IP, so anyone can lock
   out any account (per-account login DoS); without `into_make_service_with_connect_info`
   the XFF fallback is client-controlled and resets the limiter. Fix: explicit
   trusted-proxy config (CIDR); only then read the XFF hop it appended,
   otherwise use the peer address. Align the comment.

## Minor findings

5. Rate-limit `record_success` runs before `complete_login`; a DB failure after
   password verification resets the budget with no audit row. Fix: record after
   success (or `record_failure` on error).
6. No session rotation on login: previous sessions stay valid for their 7-day
   lifetime. Fix: delete the user's other sessions on login (or cap them).
7. `PLAN.md` requires the bootstrap password to be rotated; no mechanism exists.
   (Chief-of-staff: deferred to M4 user management; PLAN amended.)
8. Framework rejections (405, unknown `/api/*` 404) bypass the uniform error
   shape claimed in `error.rs:1-8`. Fix: `/api/*` fallback + method-not-allowed
   emitting `ApiError`.

11. `bootstrap.rs:11` uses `anyhow` outside the top level. (Chief-of-staff:

12. Raw `JsonRejection` text echoed into 400 bodies can embed the offending

13. `routes/auth.rs:405-411`: `SELECT actor_user_id … LIMIT 1` without

    documented; no change.
