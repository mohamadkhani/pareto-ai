## Major

- **M1. Custom header values are credential-equivalent secrets stored
  plaintext.** `catalog/headers.rs:4-9` says values may hold secrets, yet
  `headers_json` is plain JSON (`catalog/mod.rs:464-467, 1004-1007`,
  `0003_provider_catalog.sql:38, 75`). Contradicts `AGENTS.md` and D16's
  threat model. **Resolution (chief-of-staff, D17):** seal header values with
  the same `SecretBox`, AAD = row id; names stay plain.

## Minor

1. **No zeroization** of key bytes (`secrets.rs:59, 115`), the `encrypt`
   buffer (`secrets.rs:134`), or decrypted strings. `zeroize` 1.9.x is in the
   offline cache.
2. **`prices` uniqueness is app-only** — no `UNIQUE (offering_id)`
   (`0003_provider_catalog.sql:81-98`); UPDATE-then-INSERT upserts
   (`catalog/mod.rs:1253-1294, 1333-1379`). Add `UNIQUE(offering_id)` +
   `INSERT … ON CONFLICT` (also removes the `SQLITE_BUSY_SNAPSHOT` 500 window).
3. **`validate_balance_source` stores the untrimmed value**
   (`catalog/mod.rs:153-163`) — `" manual"` passes validation but violates the
   DB `CHECK` → 500 instead of 400.
4. **Secret validated with a name validator** (`catalog/mod.rs:463, 553`):
   trims the secret and caps at 200 chars (JWT/OAuth keys exceed that). Use a
   dedicated check: no trim, cap ≥ 8 KB.
5. **Sync stomps admin model edits** (`openrouter.rs:621-638`).
   **Resolution: D18** — documented, follow-up for a "manually edited" marker.
6. **`detail_json` growth** (`openrouter.rs:408-419`): raw pricing per model,
   ~75-100 KB/run at 300 models, never pruned, returned in full by `/status`.
   **Resolution: D19** — keep raw values for changed/skipped models only,
   prune beyond 30 runs.
7. **`Debug` derives on secret-carrying types** (`types.rs:31-50, 351-380`):
   `CredentialInput`, `CredentialPatch`, `CredentialRow` would print secrets if
   ever `tracing::debug!(?…)`-ed. Redact manually.

## Nits

- `per_million_field` `Number` branch (`openrouter.rs:231`) lacks `is_finite`.
- `apply_sync_price` NULLs cache prices on non-manual rows
  (`openrouter.rs:1344-1346`), which would erase a future `models_dev` row's
  cache prices.
- `SecretError::Decrypt` reused for seal failures (`secrets.rs:140`).
- `/v1` behind `csrf_guard` (`routes/mod.rs:128-134`) — M3 must exempt
  bearer-authenticated `/v1` (recorded in the M3 spec).
- Two providers with the same `upstream_model_id` duplicate `id` in
  `/v1/models` (`catalog/mod.rs:1428-1455`) — M5 dedup.
- Milestone log declares four schema deviations; the migration header documents
  two (`display_name`-in-`capabilities_json`, `GET /api/offerings/{id}/price`
  live in code docs only).
- `bad_body` duplicated (`routes/catalog.rs:24`, `routes/providers.rs:25`).
- Test gaps: `validate_balance_source`, negative/NaN price rejection, >200-char
  secret.
- OpenRouter `pricing.input_cache_read`/`input_cache_write` are not mapped to
  `cache_read_per_m`/`cache_write_per_m` (spec's field list omitted them);
  synced rows get NULL cache prices.
- Probe allows admin-directed fetch of arbitrary `base_url` (SSRF-ish) —
  accepted for a trusted admin; response is status/latency only.
